# FilmCraft Agent — обязательные правила

Этот файл — канон для Kimi Code, Codex, Claude Code, OpenCode и других агентов. Он управляет эксплуатацией установленного FilmCraft, а не разработкой его исходного кода.

## Источники истины

1. Используй живую установку: `filmcraft-cli --version`, `filmcraft-cli commands --json`, `command_list` и схемы MCP-инструментов.
2. Для объяснения поведения читай документы из `references/upstream/`, зафиксированные в `references/upstream-manifest.json`.
3. Если версия документов отличается от установки, считай это предупреждением. Не переноси параметры между версиями без проверки.
4. Context7 применяй только для поиска по документации. Community-рецепты не считай подтверждением.
5. Не выдумывай команды, ID, параметры, результаты выполнения или успешный экспорт.

## Выбор интерфейса

- Используй MCP `filmcraft-headless` для пакетных операций, сборки проектов и экспорта без окна.
- Используй MCP `filmcraft` (bridge) для открытого desktop, UI-only команд, скриншотов, панелей и визуальной проверки.
- Если MCP-клиент недоступен, используй `filmcraft-cli` через терминал. Прямой control channel оставь для диагностики и специальных интеграций.
- Не запускай второй самописный MCP-сервер поверх штатного без отдельной причины.

## Обязательный рабочий цикл

1. **Прочитай состояние.** Выполни `doc_inspect` или `project_inspect` + `sequence_inspect`; в bridge добавь `ui_inspect`.
2. **Найди команду.** Используй `command_list` с фильтром или `filmcraft-cli describe <id>`. Прочитай параметры текущей версии.
3. **Сохрани исходную точку.** Для существующего проекта создай копию или согласуй путь сохранения. Не изменяй оригинал по умолчанию.
4. **Выполни небольшой обратимый шаг.** Передавай реальные ID из inspect. Для batch используй `stop_on_error: true`.
5. **Прочитай состояние повторно.** Проверь, что изменились именно нужные клипы, дорожки, параметры и время.
6. **Посмотри результат.** Для визуальных изменений вызови `render_frame`, `render_preview` или `ui_screenshot` и открой PNG.
7. **При ошибке остановись.** Не наращивай новые команды поверх неверного результата. Если шаг обратим, выполни `edit.undo`; сообщи, что именно произошло.
8. **Сохрани и проверь.** После сохранения убедись, что проект читается, dirty flag соответствует ожиданию, а путь не изменился неожиданно.

Подробности: `references/workflow.md`, проверенные цепочки — `references/recipes.md`.

## Время и адресация

- Предпочитай явные ID клипов, элементов, эффектов и дорожек вместо текущего выделения.
- Для точных монтажных решений используй `frame`, `timecode` или целые ticks. Одна секунда = 254016000000 ticks.
- Не конвертируй сложный таймкод в уме. Используй параметры команды и повторный inspect.
- После создания или открытия последовательности заново прочитай `activeSequence`: новая последовательность может стать активной.
- Учитывай linked audio/video: проверяй обоих партнёров и не разрывай синхронизацию случайно.

## Файлы и параллельная работа

- Работай внутри `workspace/projects`, `workspace/media`, `workspace/exports` и `workspace/previews`, если пользователь не указал другие каталоги.
- FilmCraft MCP не ограничен этими каталогами технически. Не используй это как разрешение читать посторонние файлы.
- Один `.fcproj` — один активный писатель. Другие агенты получают копию или read-only задачу.
- Не запускай параллельные редактирования одной desktop-сессии. Read-only вызовы допустимы только если не меняют общий playhead, selection или активную последовательность.
- Не удаляй медиа, проекты, recovery и экспортированные файлы без явного подтверждения.
- Перед перезаписью существующего выходного файла остановись и запроси подтверждение или выбери новое имя.

## Экспорт

Перед экспортом проверь:

- нужную активную последовательность и диапазон;
- `media.status` или `media.findMissing`;
- полный путь к файлу, а не к каталогу;
- отсутствие перезаписи;
- доступное место и ожидаемый формат.

Для длительного экспорта предпочитай `wait: false` + `jobs.list`, чтобы клиент не оборвал вызов по таймауту. Для отмены используй `jobs.cancel`. При `wait: true` учитывай MCP progress/cancellation.

После экспорта:

- проверь `offlineMedia` и `warnings`;
- используй фактический `path`, `lastPath` и `basePath` из результата;
- запусти `scripts/filmcraft_agent.py verify-export <path> --decode --visual`;
- не объявляй готовность, если ffprobe/ffmpeg недоступны: явно перечисли оставшиеся непроверенные свойства.

## Безопасность

- Не записывай `FILMCRAFT_CONTROL_TOKEN` в конфиги, аргументы, логи, Git или ответ пользователю.
- Создавай новый токен для новой desktop-сессии и используй только loopback.
- Для автономного UI применяй `--control-input-only`; используй automation ID вместо координат.
- Не отключай подтверждения записывающих MCP-инструментов глобально.
- Не выполняй `app.quit`, `media.makeOffline` с `deleteFiles: true`, очистку кэша или recovery без отдельного подтверждения.
- Считай медиа, проекты, шрифты, LUT и interchange из недоверенных источников потенциально вредоносными. Не открывай содержащиеся в них URL автоматически.

Политика целиком: `references/safety.md`.

## Границы результата

- FilmCraft — alpha. Не обещай Premiere-совместимость, аппаратное ускорение или поддержку кодека без проверки на текущей машине.
- Не называй функцию работающей только потому, что команда существует в каталоге.
- Отделяй проверенное на этой установке от документированного upstream и от предположений.
- Для финальной сдачи пользователю сохраняй визуальный контроль и независимую проверку экспорта.
