# Безопасность и сохранность работы

## Классы операций

### Можно выполнять после чтения состояния

- `command_list`, `project_inspect`, `sequence_inspect`, `doc_inspect`;
- `render_frame`, `render_preview`, `ui_inspect`, `ui_elements`, `ui_screenshot`;
- локальные `probe`, синтаксические проверки и чтение документов.

Даже read-only bridge-вызовы сериализуй с действиями пользователя: некоторые визуальные операции временно используют общий playhead.

### Требуется согласие на запись в текущей сессии

- `command_run`, `command_batch`, `media_import`;
- `ui_click`, `ui_drag`, `ui_key`, `ui_type`, `ui_control`;
- сохранение рабочей копии и создание нового экспорта;
- изменение проектных MCP-конфигураций.

Используй подтверждение клиента для инструментов, не помеченных read-only. Не включай глобальное `allow` для всех MCP.

### Требуется отдельное явное подтверждение пользователя

- перезапись оригинального `.fcproj`, медиа или готового экспорта;
- удаление файлов, recovery, кэша и auto-save;
- `media.makeOffline` с `deleteFiles: true`;
- `file.revert`, `app.quit`, массовый `prefs.reset`;
- запуск команд с повышенными привилегиями;
- публикация, upload, отправка проекта или медиа в сеть;
- обновление FilmCraft и замена версионированной документации.

## Token и loopback

- Используй ровно 64 случайных hex-символа в `FILMCRAFT_CONTROL_TOKEN`.
- Создавай токен через `secrets.token_hex(32)`; wrapper делает это автоматически.
- Передавай токен только через наследуемое окружение desktop → agent → MCP child process.
- Не помещай токен в `mcp.json`, TOML, аргументы, shell history, отчёты и Git.
- Слушай только `127.0.0.1`; не пробрасывай control port в сеть.
- Не логируй окружение процесса целиком.

## Файловая граница

FilmCraft не предоставляет automation read root. Рабочие каталоги проекта — организационная, а не техническая граница. Для недоверенных задач используй отдельную ОС-сессию/пользователя или проверенную sandbox-политику агента. Не объявляй каталог безопасным только потому, что он указан как `cwd`.

## Один писатель

- Не открывай один проект на запись в двух headless-сессиях.
- Не редактируй одновременно через desktop и CLI/MCP.
- Атомарная запись предотвращает повреждение файла, но не merge конфликтов.
- Для параллельных задач создавай независимые копии проекта и разные export-каталоги.

## Smoke-тесты

Тесты обязаны использовать новый изолированный data dir и `--demo`. Запрещено направлять их на пользовательский `.fcproj`. Bridge smoke завершает только процесс, который сам создал, и не выполняет монтажных изменений.

## Недоверенные материалы

Медиа, `.fcproj`, XML/AAF/OTIO/EDL, шрифты, LUT и preset-файлы обрабатываются как небезопасный ввод. Не переходи по marker URL автоматически, не запускай вложенные скрипты и не раскрывай приватные пути/логи при публичном сообщении об ошибке.

## Конфигуратор

- Существующие JSON-настройки сохраняются; заменяются только две FilmCraft-записи.
- Codex изменяется только между маркерами managed block.
- Перед записью создаётся резервная копия в `workspace/runtime/config-backup/`.
- Существующий unmanaged FilmCraft-сервер в Codex — ошибка, а не повод перезаписать его.
- Токен в генерируемые файлы не попадает.
